# Lab dashboards

The two saved-object exports contain **three dashboards**: an Auditbeat overview,
an authentication view, and an Atomic findings comparison.

## Import and open

Inside the VM, with the stack running:

```bash
make objects
```

Open **Dashboards** in the navigation menu at http://127.0.0.1:5601 and search for
the titles below. Importing again overwrites matching saved objects, including local
dashboard edits. Index patterns are imported before dashboards and visualizations.
The [command reference](commands.md) describes timeout and failure behavior.

## Auditbeat overview

**Title:** `[Default][Auditd] Overview Dashboard`

**Export:** `config/opensearch-dashboards/objects/dashboard_auditbeat.ndjson`

**Data source:** `security-auditbeat-*` (saved index-pattern ID `auditbeat_local`).

Use this view to confirm that VM activity reaches OpenSearch and to investigate
the telemetry generated by a simulation.

| Panel | What it shows |
| --- | --- |
| Events per Atomic Technique | Event count grouped by `atomic.test`, not unique test executions. |
| Logs per Atomic Test Run Time Diagram | Events over `@timestamp`, split by `atomic.testrun`. |
| Event Category Pie Diagram | Distribution of `event.category`. |
| Event Category Time Diagram | Event categories over time. |
| Event Action Pie Diagram | Distribution of `event.action`. |
| Audit Event Table | Host, category, executable, process command line, container name and user. |
| Event Outcome Pie Diagram | Distribution of `event.outcome`, including success and failure where present. |

Atomic charts exclude records without the corresponding Atomic field. Untagged VM
activity can still appear in category/action charts and the event table.

## Authentication dashboard

**Title:** `[Default][Auditd] Authentication Dashboard (Login)`

**Export:** also `dashboard_auditbeat.ndjson`.

**Data source:** `security-auditbeat-*`, restricted to
`event.category:authentication` in each saved visualization/search.

This dashboard contains:

- Outcome pie chart and outcome timeline for authentication events.
- User-name and hostname breakdowns.
- A detailed event table with host, category, action, type, outcome, audit actors,
  audit object, and user name.

Use it to investigate login activity. A process-discovery simulation does not
necessarily generate authentication events, so an empty view can be expected.

## Atomic findings overview

**Title:** `Atomic | Findings Overview Dashboard`

**Export:** `config/opensearch-dashboards/objects/dashboard_findings.ndjson`

This dashboard combines raw audit telemetry with the on-demand enriched findings
view, `securtiy-findings-view`. The index spelling is intentional for compatibility.

| Panel | Data source | Grouping or displayed fields |
| --- | --- | --- |
| Events per Atomic Test | Auditbeat | `atomic.test` |
| Events per Atomic Testrun | Auditbeat | `atomic.testrun` |
| Events per Atomic Name | Auditbeat | `atomic.name` |
| Records per Rule | Enriched findings | `rule.name` |
| Records per Atomic Technique | Enriched findings | `atomic.test` |
| Auditd Event Table | Auditbeat | Executable, category, command line and user |
| Findings Event Table | Enriched findings | `document.process.title`, `rule.name`, `rule.query` |

Create a detector and generate findings before running `make findings`. Importing
saved objects alone does not populate the findings index. Rerun the importer after
new detector results; refreshing the browser does not invoke it.
